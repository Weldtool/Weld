%% ── Abstract ────────────────────────────────────────────────────────────────
\begin{abstract}
Developers routinely switch between disconnected tools---task boards, team
chat, and code-review platforms---incurring context-switching costs that reduce
productivity and increase cognitive load. Integrated developer workspaces
promise to alleviate this fragmentation, yet the additional benefit of
embedding AI agents that can observe and act across multiple surfaces remains
poorly understood, as does the question of how the \emph{breadth} of context
made available to such agents shapes their effectiveness. We present \textsc{Weld},
an all-in-one developer workspace that unifies a Kanban task board, team chat,
and GitHub integration in a single product, and report a controlled
between-subjects user study ($N$~=~\emph{TBD}, three conditions, balanced
block-randomization) that manipulates how much workspace context an embedded AI
agent can access. Participants completed 12 tasks spanning three
categories---comprehension, single-surface, and cross-surface
coordination---first in a no-agent baseline phase and then in their assigned
agent condition: $C_1$ (chat context only, advisory), $C_2$ (chat and board,
action-capable), or $C_3$ (chat, board, and GitHub, full action). We collected
task completion rates, time-on-task, NASA Task Load Index (NASA-TLX, six
subscales), System Usability Scale (SUS), a five-item integration-perception
scale, an eight-item AI trust and effectiveness scale, and approximately 40
categories of fine-grained in-product telemetry events. Context scoping was
enforced at the server in code via a Context Gate module---not via prompt
instructions---making the manipulation provable from audit logs. Results will
be reported upon study completion. Our primary contribution is a code-enforced
context-scoping mechanism as a replicable design principle for studying and
deploying AI agents in multi-surface collaborative tools, together with an
empirical characterisation of how context breadth interacts with task type to
determine agent benefit in realistic developer workflows.
\end{abstract}
